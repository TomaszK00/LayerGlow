# LayerGlow audit — 25 October 2026

## Scope and baseline

Reviewed main at `31bef10169ba411b4347ae0342ea5ca32d73e57e` (v2.45): firmware, embedded web UI, persistence, network recovery, printer adapters, OTA and release workflow. Verified the published binary size/SHA-256, source parity and successful v2.45 Actions build. Parsed scripts and checked translation coverage for EN/PL/ES/DE.

This is a code review and host-side regression audit. No physical ESP32-C3, real printer, actual Android native colour picker, network soak test or penetration test was available. It is not a security certification or a complete third-party dependency/CVE assessment.

## Open security/product decisions

- Web/OTA administration has no per-device login and the AP has a shared default password. Decide pairing/admin recovery and unique AP credentials before selling kits. Same-origin checks do not resolve this.
- Bambu uses `setInsecure()`. Certificate trust/pinning needs a tested provisioning/recovery design for the supported printer models.
- MQTT connect is still synchronous on the main task and can stall it during TLS negotiation; HTTP reads have been moved out. Measure before deciding whether to move MQTT ownership to a worker too.
- No project-level signed firmware trust chain or tested automatic rollback/boot acceptance is provided. SHA-256 from the GitHub manifest checks download integrity, not an independent firmware signature.
- Discovery probes the controller's local /24 (further constrained by its subnet mask); printers elsewhere in a larger LAN may need manual IP setup. PrusaLink discovery is not implemented.
- The browser, not the controller, checks GitHub. Automatic checks are skipped while setup AP is active. The update LED flag is volatile and requires a browser check.
- Memory allocation, radio behaviour, real certificates and API compatibility cannot be established by host fakes. Do not infer support for every printer model from the adapter menu.

## Hardware acceptance for published v2.46 test candidate

1. Record baseline `/api/health` and `/api/ota/capacity`; install the candidate through GitHub update or manually with power connected.
2. Check K2 live readings and web response while printer is off/unreachable, then restore it. Repeat with Bambu, including router loss, MQTT loss and fresh reports for at least one hour.
3. Save two Wi-Fi networks, remove the current network from range and keep a phone on the AP. Verify automatic fallback, AP availability, scan and recovery. Repeat router power cycling and locations/channels.
4. Change colours/brightness/pulse, back up, reboot and restore. In Android Chrome confirm the native picker shows the remembered suggestion; this cannot be proven by DOM tests.
5. Test OTA to a newer version and reflash the same version; verify new boot ID and correct UI recovery. Test rejected oversized/invalid upload without interrupting a valid flash write.
6. Check 5, 24, 48 and 300 configured LEDs, preview in mobile/desktop widths, four languages and three themes. Confirm physical LED type, power and wiring independently.
7. Run 24-hour network/printer soak with repeated `/api/health` measurements: free/minimum heap, response time, reconnect count and resets. v2.46 is a candidate until these checks pass.
